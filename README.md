# VideoMaker

本地运行的网页动画导出工具：**手动逐帧渲染 → PNG 序列 → FFmpeg → 无音频 MP4 / H.264 / 60 fps**。

使用中文网页界面设置目标 URL、输出尺寸、时间区间和画质；目标网页必须接入 [逐帧协议 v1](docs/protocol-v1.md)。工具不要求网页在现实时间中达到 60 fps，渲染速度只影响等待时间。

## 安装与启动

需要 **Node.js 22.18 或以上版本**、FFmpeg 和 FFprobe（包含 `libx264` 编码器）。FFmpeg 与 FFprobe 均须加入系统 PATH。

```bash
npm ci
npm run install:browser
npm start
```

打开 **http://127.0.0.1:3333**。Linux 如缺少浏览器系统依赖，可执行 `npx playwright install --with-deps chromium`；导出中文内容还应安装中文字体，例如 `fonts-noto-cjk`，或由目标项目自带字体。首次安装需要联网；之后可导出资源全部在本机的网页。

1. 先启动要导出的网页项目，例如运行该项目的 `npm run dev`。
2. 把它的完整 HTTP/HTTPS 地址填入 VideoMaker。已部署的网页也可以直接填写网址。
3. 点击「读取信息」，检查接口、动画时长、推荐布局及本次帧数。
4. 选择 1080p、4K 或自定义尺寸，设置区间，点击「开始导出」。
5. 完成后预览或下载 MP4。可以先用内置的 6 秒示例试跑。

目标网页运行在你的电脑上时，VideoMaker 也应在同一台电脑运行：`localhost` 指向运行导出器的机器。网页需要登录的情况暂不支持复用日常浏览器的会话。

## 尺寸与时间

- 帧率固定 **60 fps**；无音频；视频保留网页背景。
- **布局尺寸**控制 CSS 排版，**输出尺寸**控制 PNG 和视频像素。默认布局为 1920×1080，4K 按 2 倍 DPR 渲染，不经过后期插值放大。Canvas/WebGL 项目须响应 `deviceScaleFactor`，提高内部位图尺寸。
- 自定义输出支持同宽高比、0.25～4 倍 DPR；宽高必须为偶数，单边不超过 8192，总像素不超过 33,554,432。其他比例可同时修改布局和输出，例如 1440×1080 或 1080×1920。
- 时间在界面中以秒输入，协议内部用毫秒。第 `n` 帧时间直接计算为 `n × 1000 / 60`。
- 时间区间 `[start, end)` 选取落入其中的全局采样帧。实际视频时长为 `帧数 / 60`；不整帧区间可能略有量化差异，任务信息记录实际起止时间。
- 不支持跳转的网页从 0 帧开始预推进，只保存导出区间的 PNG。预推进也按完整帧步长调用，不快进、不跳步。
- 默认 CRF 为 18；更小的值表示更高画质、更大文件。`fast / medium / slow` 调整编码速度。

## 输出与任务

默认保存在项目目录下的 `exports/<任务ID>/`：

```text
job.json                   配置、帧计划、进度、浏览器版本、失败信息和视频校验结果
frames/frame-00000000.png   连续编号的 PNG，编号从 0 开始
frames/frame-00000001.png
...
video.mp4                  校验通过后才作为完成结果提供
```

同一时间只执行一个导出任务，最多额外排队 5 个，避免多个高分辨率浏览器互相争抢资源。进度按阶段展示。截图失败不跳过该帧；已生成 PNG 保留。取消不会删除文件。重启服务会加载任务记录，并把未完成任务标为失败，不自动接着渲染有历史状态的网页。

PNG 完整时，「按当前画质重新编码」只读取 PNG，使用界面当前 CRF/编码速度，不再启动目标网页。编码前检查编号、帧数与 PNG 尺寸；编码后使用 FFprobe 解码计数，校验 H.264、无音频、尺寸、60 fps、帧数与时长。损坏 PNG 会导致编码失败。

## 环境配置

| 环境变量        | 默认值                   | 用途                                                   |
| --------------- | ------------------------ | ------------------------------------------------------ |
| `PORT`          | `3333`                   | 本机操作界面端口                                       |
| `OUTPUT_DIR`    | 项目内 `exports`         | 导出目录，相对路径按当前工作目录解析                   |
| `FFMPEG_PATH`   | `ffmpeg`                 | FFmpeg 可执行文件路径                                  |
| `FFPROBE_PATH`  | `ffprobe`                | FFprobe 可执行文件路径                                 |
| `CHROMIUM_PATH` | Playwright 配套 Chromium | 指定已有浏览器用于诊断；正式导出建议使用固定的配套版本 |

服务绑定 `127.0.0.1`，仅供本机使用。输出任务中的 URL 不应包含敏感访问令牌。导出器不会自动安装或启动目标项目。

## 开发与验证

```bash
npm run dev                 # 修改后自动重启后端
npm run check               # TypeScript 类型检查
npm run format:check        # 格式检查
npm test                    # 参数、帧计划、序列和编码异常检查
npm run test:integration    # 真实 Chromium + PNG + FFmpeg 的端到端检查
```

集成测试覆盖重复渲染逐帧哈希、顺序预推进、1080p/4K 输出、无音频 60 fps、取消、接口超时/异常与重新编码。测试结果写入系统临时目录并在结束后删除。

源码采用 Node.js 原生 TypeScript 类型擦除，启动不需要构建；类型检查单独由 TypeScript 执行。`public/` 为静态界面，`src/` 为导出器和本地 HTTP 服务，`example/` 为可改造的示例，`docs/` 为接入文档。

固定随机种子、浏览器、系统、字体和 GPU 环境有助于复现画面。跨机器逐字节一致不在 v1 保证范围内；图片、字体、数据、视频解码和 WebGL 完成状态须由目标网页正确处理。第一版不支持音频、透明视频、自动启动项目、跨任务续渲染或未经接入的普通网页。
